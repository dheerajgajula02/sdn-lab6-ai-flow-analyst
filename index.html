Lab 6: The AI Flow Analyst

Turning Raw OpenFlow Telemetry into Autonomous AI Diagnoses

🛠️ Labs 1–5 (Old Way)

You write every rule by hand: "If packets on port > 100, execute iptables drop". Rigid, fragile, misses zero-day anomalies, breaks on unseen traffic patterns.

VS

🧠 Lab 6 (AI Way)

The LLM reasons about the network: You dump live flow tables & port counters, hand it to the AI as a network brief, and it spots floods and rogue drops just like a human engineer.

⚡ The 4-Stage System Architecture
STAGE 1
Objective 1: The Sensor
Mininet + OVS + Ryu

Collects raw network ground truth into a single Python dictionary:

Ryu REST API (:8080) Flows
ovs-ofctl dump-ports Rx/Tx Bytes
ovs-vsctl show Status

Two injected traps for the AI to find:

h1 ➔ h4 UDP Flood iperf 50M
s1 Rogue DROP rule Drop h2
Output: collect_complete_network_state()
STAGE 2
Objective 2: Free-Text AI
format_for_llm + Prompt

Raw JSON is messy for LLMs. This cleans it into an executive network brief:

// Prompt Context
"You are a Senior Network Engineer. Analyze this flow table & port stats. Flag anomalies."

LLM reasoning output:

Plain English

"Anomaly 1: Port 4 has 45,000x higher byte count due to UDP flood. Anomaly 2: Rule on s1 dropping MAC ...02 traffic."

Output: analyze_network() (Free Text)
STAGE 3
Objective 3: Machine JSON
Strict Schema + Retries

Scripts can't parse free text. We lock the LLM to pure JSON:

{
  "network_health": "warning",
  "anomalies_detected": [{
    "type": "Traffic Flood",
    "affected_device": "s1-eth4",
    "severity": "high"
  }],
  "summary": "..."
}

Defensive Reliability:

Parse JSON Failure Auto-Retry 1x
Tested on 3 scenarios: Normal, Flood, Drop.
STAGE 4
Objective 4: 24/7 Loop
Continuous Sentinel

Autonomous loop polling network every 30 seconds:

Iteration Interval 30 seconds
State Comparison T vs T-1

Alert Trigger:

🚨 ALERT

Status changed: normal ➔ warning. Anomaly detected on s1.

Output: Timestamped Terminal Monitor
